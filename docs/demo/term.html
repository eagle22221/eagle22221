vex identifies these techniques; it does not defeat them.

Anti-debugging  [high]
  - imports CheckRemoteDebuggerPresent
  - imports GetTickCount
  - imports IsDebuggerPresent
  - imports NtQueryInformationProcess
  - imports OutputDebugStringA
  The program checks whether it is being debugged and can hide, change its behaviour or refuse to run. Common in anti-cheat, DRM and malware.

Virtual-machine or sandbox checks  [high]
  - string "SbieDll.dll"
  - string "VBoxGuest"
  - string "qemu-ga"
  - string "vboxservice"
  - string "vmci.sys"
  - string "vmtoolsd"
  The program looks for signs that it is running in a virtual machine or an analysis sandbox, which it may use to behave differently when watched.

API or input hooking  [high]
  - imports SetWindowsHookExW
  The program can intercept calls, messages or input that belong to other software. Used by overlays, cheats, key loggers and anti-cheat.

Process injection  [high]
  - imports CreateRemoteThread
  - imports VirtualAllocEx
  - imports WriteProcessMemory
  The program can write code or data into another running process and execute it. Game cheats use this to get inside a game; some anti-cheat and much malware use it too.

Packing or protection  [high]
  - section "UPX1" (UPX)
  - section "UPX1" entropy 7.55 of 8
  The program's code is compressed or protected, so most of it cannot be read until the program unpacks itself in memory at run time. Packers and protectors are used by anti-cheat, DRM and malware alike; to read the real code you would run it under a debugger and dump it.
