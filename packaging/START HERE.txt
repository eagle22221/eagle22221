vex for Windows
===============
Developed by SS

vex takes a program apart and shows what is inside it, without running
it. It reads Windows programs (.exe, .dll) and Linux programs. There is
nothing to install, and it does not need Python.


The quickest start
------------------

Double-click vex-app.exe. vex opens in a window of its own, with its own
title bar, icon and taskbar button, like any installed program: no web
browser and no console window. Everything happens on your own computer
(nothing is uploaded, and the file you look at is never run). Choose
"Open File" and pick a program, or drag any .exe or .dll onto vex-app.exe
to open it straight away. Try it with practice\hello_pe64.exe. Closing the
window quits vex.

The first start on a computer can take a few seconds; the window says
"Starting vex..." while it gets ready.

When vex starts, its logo plays a short opening animation; a click, Esc,
Enter or Space skips it. The gear button at the top right switches between
the dark and the light look and turns the animated background off.

Each file you open gets a tab of its own at the top; "+" next to the tabs
opens another. The Overview comes first: what the file is, how it is
protected, a map of its parts and an entropy chart. The sidebar on the left
lists the other views in three groups:

    Analysis    Techniques (anti-debug, VM checks, injection, hooking,
                packing), Code (the instructions, grouped into functions),
                Strings, Imports, Exports, Sections and Bytes (hex)
    Resources   Assets (game asset packs)
    Advanced    Entropy (a chart of how random the bytes are along the
                file), Split (save the parts of the program as separate
                files), Decode (a decode and cipher workbench) and
                Patching / Modify

"Export Report", on the card at the top of each file, downloads a summary
of what vex found, as Markdown or as JSON.

This folder holds three program files:

    vex-app.exe          the app: double-click it to start vex
    vex.exe              the same tool for the terminal (all the commands)
    WebView2Loader.dll   a small Microsoft file the app needs; it must stay
                         in the same folder as vex-app.exe

Prefer the terminal? Everything is also a command (see below), including
a report you can read without the app:

    .\vex.exe report practice\hello_pe64.exe


Using commands
--------------

For more control, open a terminal in this folder: hold Shift, right-click
an empty part of the folder and choose "Open PowerShell window here" (or
"Open in Terminal"). Then type a command:

    .\vex.exe info practice\hello_pe64.exe

    Command                              Shows
    -----------------------------------  -------------------------------------
    info FILE                            what the file is, hashes, protections
    report FILE                          everything at a glance
    sections FILE                        the parts of the file, with entropy
    entropy FILE                         how random the bytes are along the
                                         file (packed parts come close to 8)
    imports FILE                         system functions the program uses
    exports FILE                         functions a library offers
    symbols FILE                         names kept in the file
    strings FILE                         readable text in the file
    strings FILE --grep TEXT             only strings containing TEXT
    strings FILE --tagged                only links, addresses and paths
    hexdump FILE 0x140002000             raw bytes at an address
    functions FILE                       the functions found in the code
    disasm FILE NAME                     the instructions of one function
    xrefs FILE NAME                      where a function or import is used
    xrefs FILE --string TEXT             where a piece of text is used
    techniques FILE                      packing, anti-debug, anti-VM,
                                         injection, hooking, driver checks
                                         (useful for cheats and anti-cheat)
    split FILE FOLDER                    save a program's parts, and the files
                                         found inside it, into a new folder
    decode --text TEXT --recipe "op|op"  decode, un-zip and decipher data you
                                         give it (ciphers need the key)
    engine FOLDER                        a game's engine and its asset packs
    assets list PACK                     files in a .pk3/.pak/.wad/.pck pack
    assets extract PACK FOLDER           unpack a pack
    assets replace PACK NAME FILE -o NEW write a new pack with a file replaced
    patch bytes FILE 0x1400.. "90 90"    change bytes (into a copy)
    gui                                  open the app window, like vex-app.exe
    gui --browser                        open it in a web browser tab instead

Add --json right after vex.exe to get output other tools can read:

    .\vex.exe --json imports practice\hello_pe64.exe

For the options of any command:  .\vex.exe COMMAND --help


Five short lessons
------------------

Use practice\hello_pe64.exe, a tiny program that prints two lines of text.

1. What is it?
       .\vex.exe info practice\hello_pe64.exe
   Read the first lines: Windows or Linux, 32 or 64 bit, where the code
   starts ("entry point"), and which protections it was built with.

2. Where is everything?
       .\vex.exe sections practice\hello_pe64.exe
   ".text" is the code, ".rdata" holds text and constants. Entropy near 8
   means compressed contents. To see it along the whole file:
       .\vex.exe entropy practice\hello_pe64.exe

3. What text does it carry?
       .\vex.exe strings practice\hello_pe64.exe --grep fixture
   Programs keep their messages and web addresses as plain text. They are
   the quickest way to see what a program is about.

4. Which code uses that text?
       .\vex.exe xrefs practice\hello_pe64.exe --string "Hello from"
   The answer names the function that reads the text. Then read it:
       .\vex.exe disasm practice\hello_pe64.exe entry
   Lines starting with "call" run another function; the note after the
   semicolon says which one.

5. What does it ask Windows to do?
       .\vex.exe imports practice\hello_pe64.exe
   Functions such as WriteFile or CreateFile mean it works with files;
   socket or connect mean it uses the network.


Good to know
------------

- vex never runs the file you give it. It only reads it.
- Keep vex-app.exe, vex.exe and WebView2Loader.dll together in one folder.
  If you move vex, move the whole folder.
- Windows may warn about vex-app.exe or vex.exe the first time ("Windows
  protected your PC", "unknown publisher"), because they are not digitally
  signed. Choose "More info", then "Run anyway" if you trust where you got
  them.
- The window uses Microsoft Edge WebView2, the web engine built into
  Windows 11 and into Windows 10 computers that have Microsoft Edge. If it
  is missing, vex opens in a plain Edge or Chrome app window instead (still
  no tabs or address bar). If neither browser is there, vex opens in your
  normal web browser, and a small "vex is running" box lets you stop it.
  Whichever way it opens, everything stays on your own computer.
- The practice folder has more to try: sample.dll and libsample.so (a Linux
  library) for "exports"; evasion_pe64.exe, a harmless sample that trips
  every check, for "techniques"; and demo_game\ (a pretend game) for
  "engine" and the Assets view, e.g.  .\vex.exe engine practice\demo_game
- "split" saves the parts of a program as separate files. To try it, use
  practice\bundle_pe64.exe, a harmless hello-world program with a picture, a
  sound and a zip archive attached to its end:
      .\vex.exe split practice\bundle_pe64.exe bundle_parts
  The new folder bundle_parts gets "parts" (the program cut into its parts,
  in order), "embedded" (the picture, the sound and the zip archive) and
  index.txt, a list of every piece. Read index.txt first. The folder must be
  new or empty. The original is not changed and nothing is run.
- "split" only copies what is already in the file. It does not unpack,
  decrypt or decompress anything, so packed or encrypted content comes out
  exactly as stored, and it cannot turn a program back into source code.
  Joining the files in "parts" in order gives the original file again
  (index.txt notes any stretch of empty filler that was left out).
- This edition saves the parts and the embedded files. Saving Windows
  resources (icons, version info) as files is in the Python edition.
- "decode" is a workbench for turning encoded or encrypted data you already
  have back into something readable: base64, hex and other encodings, un-zip
  (gzip, zlib, bzip2, xz), classic ciphers, and decryption with a key you
  supply. It never recovers an unknown key and never breaks encryption or
  protection, so content you do not have the key for stays unreadable. This
  edition does the encodings, the classic ciphers, XOR, RC4 and ChaCha20; AES
  and a few others are in the Python edition, and the Decode view greys out
  whatever the edition you are running cannot do.
- These three files do everything above - the app, the analysis and
  disassembly, the techniques scan, game asset packs and patching - with
  nothing to install. The Python edition of vex adds a few extras: editing
  icons and other resources inside Windows programs, Electron (.asar) and
  Ren'Py (.rpa) packs, and an illustrated PDF guide.
- The disassembler inside vex is Capstone (BSD licence); its licence
  text is in the licences folder.
